为什么这一关是"离线模拟器"

原型链污染只能在 JavaScript 里真实发生。本页把原 Node 服务端（_original/server.js）的资料对象与 merge 函数逐字搬进了你的浏览器： 下面提交的 JSON 会被那份真实代码合并，污染发生在你当前页面真实的 Object.prototype 上——和污染一个 Node 进程在机制上完全相同，只是"进程"换成了"页面"。

页面上的按钮对应原 API：保存资料（原 POST /api/profile）、查看资料（GET /api/profile）、访问开关（GET /api/flag）、清理污染（/api/reset）。

知识点讲解

页面里的合并函数（朴素递归 merge，与原服务端逐字一致，未过滤危险键）：

function merge(dst, src) {
  for (const k in src) {
    if (src[k] !== null && typeof src[k] === 'object') {
      if (dst[k] === null || typeof dst[k] !== 'object') dst[k] = {};
      merge(dst[k], src[k]);        // ← k 为 "__proto__" 时，dst["__proto__"] 命中原型 getter → Object.prototype
    } else dst[k] = src[k];
  }
}

原型链污染（Prototype Pollution）：JS 对象查属性时沿原型链上溯。obj["__proto__"] 的 getter 返回其原型； 递归 merge 拿它当"子对象"继续写，就把键值写进了 Object.prototype——此后所有对象（包括别处新造的 const gate = {}）都会"继承"这些属性。

payload 形态（JSON 里带一层 __proto__）：

{ "__proto__": { "admin": true } }

历史漏洞家族：lodash _.merge/_.set（CVE-2018-3721 / CVE-2020-8203）、jQuery $.extend(true,…)、 qs、各类 deep-merge 工具。危害：改权限开关（本关）、改模板引擎选项进而在编译期注入代码（下一关 RCE）、 影响 Node 子进程参数（child_process options 污染 NODE_OPTIONS）等。

渐进提示

提示 1：先玩普通字段

保存 {"nickname":"pwn"}，再「查看当前资料」看 merge 是否生效（深合并，未提及的字段保留）。

提示 2：merge 会"追进"嵌套对象

提交 {"a":{"b":1}} 会递归处理嵌套。那键名写成 __proto__ 呢？注意两个细节：JSON.parse 会把 __proto__ 变成自有属性（读 src["__proto__"] 拿到的是你给的对象）；而资料对象没有这个自有属性，读 dst["__proto__"] 走的是 getter——拿到的是它的原型。

提示 3：payload

资料 JSON 改成 {"__proto__":{"admin":true}} 点「保存资料」，然后点「访问开关」——空对象 gate 从原型链上"继承"了 admin=true，flag 出现在结果区。做完点「清理污染」方便重试。
